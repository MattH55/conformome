# Handoff

State of Conformome on 2026-10-19, for whoever picks it up next. Read this first, then `README.md`, `docs/METHODS.md` and `docs/PILOT_REPORT.md`.

## What it is

A static website and the pipeline that builds it: one page per protein (keyed on UniProt accession) listing every experimental entry that has probed the protein's conformation, from each technique's own angle, mapped onto shared conformational states. Each state and model is labelled **observed** (resolved directly by a structure) or **inferred** (fitted to indirect measurements, with its assumptions listed). Every number on the site is regenerated by `make`; nothing is hand-edited HTML.

Sister project: SMASH-BIO (https://smash-bio.org, repository `MattH55/smash-bio`). Conformome reads its release file; it does not use or copy its code.

## How to run it

```sh
pip install -e ".[test]"        # Python 3.11+
make download                   # network; about 45 minutes for 81 proteins from an empty cache
make site                       # ingest -> map -> models -> site/dist/
make validate                   # site + schema, reference, licence, link and search checks + tests
ACC="P69441 P0DP23" make site   # limit to some proteins
```

Raw downloads go to `data/raw/` (git-ignored, with an HTTP cache in `data/raw/_cache` that never expires; delete it to refetch). `data/MANIFEST.json` (committed) records every raw file's URLs, date and SHA-256.

## How it is built

| Step | Code | Output |
|---|---|---|
| download | `conformome/pipeline.py: download`, one module per source in `conformome/sources/` | `data/raw/<source>/<acc>.json` |
| ingest | `pipeline.ingest`; each source's `parse()` | `build/<acc>/evidence.json`, `ingest.json` (what was skipped and why), `molecule.json` |
| map | `pipeline.map_protein`, `mapping/rules.py`, `mapping/conflicts.py` | `build/<acc>/mapped.json` (states, mappings, ambiguous items, conflicts, coverage grid) |
| models | `pipeline.models` | representative PDB/mmCIF files for observed states |
| site | `conformome/site/build.py` | `site/dist/`: home, `proteins/`, `protein/<acc>/`, `technique/<id>/`, `search/`, `about/`, `downloads/` |
| validate | `conformome/validate.py` | error list; CI fails on any |

Record types and their JSON Schemas are in `schema/`. Techniques (basis, prediction flag, observables) are in `taxonomy/techniques.yaml`; evidence with a technique or observable not listed there fails validation.

## Curation

- `targets.yaml` lists every protein built, with the batch it came from (`pilot-1`, `pilot-2`, `multi-source-1`). The validator requires every curation file to be listed.
- `curation/<acc>.yaml` holds states, curator assignments (by evidence ID or `pdb:` ID) and rules. Field reference: `curation/README.md`.
- Rules match on technique, source, ligands, ligand text, title words and publication title. Each mapping cites `rule:<id>` with its confidence and justification. A curator assignment wins over rules; items matched by rules for different states stay unmapped and are listed as ambiguous.
- Review the low-confidence rules first (list in `docs/PILOT_REPORT.md`).

## Deployment

- `.github/workflows/deploy.yml` runs on every push to the default branch (and by hand): download → `make validate` → publish `site/dist`. It takes about 15 minutes with a warm cache.
- `data/raw` is cached per ISO week, keyed on `targets.yaml` and the curation files: pushes within a week reuse it, and each new week refetches everything.
- Deploys queue instead of cancelling, so a long build can save its cache.
- `.github/workflows/ci.yml` runs the same validation on pull requests.
- `.github/workflows/build-all.yml` runs the full download and build for every molecule on pushes to `claude/**` branches (and on demand) without publishing. It uploads `site/dist`, `build-summary.md` (one row per molecule, from `python -m conformome.summary`), the manifest and any download failures as the `conformome-site` artifact (kept 14 days). `build/` is not uploaded because it holds records whose licence forbids redistribution.
- Pages must stay on **Source: GitHub Actions**. On "Deploy from a branch", GitHub publishes the README instead of the site.
- The root `CNAME` file was created by GitHub when the custom domain was set; `site/dist/CNAME` is written by the build.
- Links to repository files use `blob/HEAD`, because there is no `main` branch. If the default branch is renamed, nothing else needs to change.

## Known issues

1. ~~**False conflicts**~~ Fixed (WP1, 2026-10-20). The old note claimed 33 of the 52 flagged
   conflicts compared alpha-synuclein **K-to-R mutants** at different salt. That diagnosis was
   wrong: no SASBDB alpha-synuclein deposit is a mutant - every sample name reads `WT`, and the
   construct carries no mutation. The disagreement was **salt**. SASBDB records the salt
   concentration in `experiment.sample.name` ("alpha-Synuclein WT 1.16mg/ml 100 mM NaCl"), while
   the parser read only `experiment.buffer.name` ("20mM HEPES") and took its leading number as
   the salt, so all eight salt levels looked like `salt_mM = 20` and every pair was comparable.
   `conformome/sources/sasbdb.py` now reads salts, ionic species and construct variants from every
   free-text field of the deposit (see WP1 below), with the raw strings kept in `conditions.notes`.
   A full-corpus rerun on identical inputs takes the 52 release conflicts to **32 removed and 20
   still comparable**, and of those 20 only one clears 3 sigma (hen lysozyme fibrils SASDMJ4 vs
   SASDMY3). The removed pairs, with codes and reasons, are listed under **WP1** below.
2. **Conflict detection is narrow, not broken.** Comparable means every one of environment, buffer
   text, temperature, pH, salt, ion list, ligand set and construct matches; `b5427f3` also made a
   missing ion list incomparable. Only SASBDB records enough conditions to clear all of those gates,
   and only NAKB (proteins: none) filled `ions` before WP1. On the pre-WP1 build, 5,096 of the 5,134
   mapped records failed before the ion check (no buffer, temperature, pH or salt), and the 38 that
   reached it were all SASBDB and all failed for having no ion list - so exactly one source could be
   compared and it was the one source with no ion data. The reported `not_compared` was 5,131 of
   5,134: the corpus showed **0 conflicts because nothing was ever compared**, not because the data
   agree. WP1 fills `ions` and a correct `salt_mM` for SASBDB; the pairs whose deposit states no salt
   are still not compared, and each page's `not_compared` count is where that stays visible. Filling
   buffer, salt and ion data for BMRB, PDB and DisProt is open work, not a parser bug.

3. **Paralogs**: CALM2 and CALM3 entries (identical sequence to CALM1) are not on the calmodulin page.
4. **Empty inferred states**: 5 inferred states have no evidence (unfolded BPTI, CI2, spectrin SH3, Pin1; cyclophilin A minor state).
5. ~~Unmapped fibrils~~ Fixed: hen lysozyme now has an observed `HEWL-fibril` state (representative 9J0L; polymorphs 9J0L/9J0M/8QV8 pooled, rule `hewl-fibril-structures`, medium confidence). Draft, unreviewed; whether polymorphs deserve separate states is a curator call.
6. **Skipped entries**: 14 powder-diffraction entries are skipped (could count as `xray`).
7. **RMSD rule**: implemented and tested, not run (it needs coordinates for about 17,000 entities).
8. **Missing content**: no transitions, no fitted models for inferred states, isoforms only partly handled.
9. **Tau has no DisProt evidence on the canonical page** (deferred; WP1 "Isoform numbering").
   `curation/P10636.yaml` defines `tau-disordered` for exactly the disorder evidence DisProt holds,
   and its rule (`title_any: ["disorder, residues"]`) does match 8 of the 16 tau region titles. The
   evidence never reaches the page because DisProt curates tau on the isoform entries `P10636-8`
   (15 structural regions) and `P10636-2` (1), never on `P10636`, while `sources/disprot.py` keeps an
   entry on its own accession only. `ingest P10636` therefore reports `DisProt: 0 evidence_items,
   not_ingested: []`: the silence is the isoform rule working as designed, not a mapping failure.
   The fix is the WP1 Isoform numbering line - map isoform regions onto canonical numbering by
   aligning the UniProt isoform sequence and keep the original range - which is a mapping and schema
   change and is left to its own pull request. Related open DisProt gaps: 8 of the 56 ECO method
   names in the corpus are structural but unmapped (`gel-filtration`, the hyphenated
   `hydrogen-deuterium exchange`, HSQC, temperature-induced unfolding, cleavage assay, atomic force
   microscopy, and the catch-alls `spectrometry` and `experimental evidence`). The WP1 "DisProt
   methods" line says to map such names only when a technique id fits exactly, so the catch-alls
   should stay in `not_ingested` with their reason.

## Molecule schema (2026-10-19)

- Records are keyed on `molecule_id` (was `uniprot`) in every schema. Patterns: UniProt (isoform suffix allowed), RNAcentral `URS…`, `DNA-<12 hex of SHA-256 of sequence>` (`conformome/molecule.py: dna_id`), `CPX-…` for complexes. For proteins the ID is unchanged, so URLs and curation file names are unchanged.
- `schema/protein.schema.json` is replaced by `molecule.schema.json` (`molecule_type`, `identifiers` for UniProt/isoform/RNAcentral/Rfam/GenBank/NAKB/PDB, `modifications` (UniProt "Modified residue" features fill it for proteins), `components` for complexes). The build file is `build/<id>/molecule.json` and the all-records download uses `record_type: molecule`.
- New: `mutational_effect.schema.json`, `state_vocabulary.schema.json` and six vocabularies in `taxonomy/state_vocabularies/` (DOIs checked against Crossref). States gain `secondary_structure`, `family_label`, `population`; evidence gains `profile`; transitions gain `kinetics` (Φ-values as a profile); models accept `dot-bracket`; conditions gain required `ions`; mappings gain optional `agreement` (score + method, for profile-vs-dot-bracket mapping).
- Applied: GPCRdb labels on β2AR states, KLIFS labels on three Abl states (draft, unreviewed).
- Not done: complexes (`ingest` raises NotImplementedError), probing sources (RMDB, RASP) and for mutational effects and kinetics (ProThermDB, mega-scale dataset, MaveDB, ClinVar, PFDB), profile-to-dot-bracket mapping, the six nucleic-acid pilot molecules, and site pages for non-protein molecules.

## Nucleic-acid sources (2026-10-19)

- `conformome/rnacentral.py` builds RNA molecule records (like `protein.py` for UniProt). RNA pages are keyed on the species-specific `URS…_<taxid>`.
- `conformome/dna.py` builds DNA records from the `anchor_pdb` given in `targets.yaml`; the anchor's DNA chain is the sequence, and the target's `molecule_id` must equal `dna_id(sequence)`.
- `sources/nakb.py` (RNA and DNA): NAKB's Solr index (`/node/solr/nakb/select`, linked from its download page; there is no documented API). Candidates: chains of exactly the molecule's sequence (`naseq`), entities RCSB's sequence search finds at >=90% identity, and, for RNA, chains Rfam assigns to the same family in the same organism. Other constructs must be 0.8-1.25x the molecule's length, so larger RNAs containing it (whole introns around P4-P6, mRNAs in ribosomes) are skipped with a reason. When RNAcentral files the molecule as a synthetic construct (taxon 32630), the organism is taken from NAKB's exact-sequence chains. Each item says which rule matched.
- `sources/rfam.py` (RNA): one `rfam_covariation` item per family hit, flagged as a prediction. The family consensus (`SS_cons`) is kept in the raw file but not projected onto the sequence (needs Infernal `cmalign`).
- Sources declare `MOLECULE_TYPES`; protein sources default to proteins only. BMRB is queried for RNA and DNA by BLAST on the sequence (>=90% coverage and identity): the telomeric G-quadruplex gets 25 entries, the riboswitch none. SASBDB is not yet queried for nucleic acids. BMRB sample components fill `conditions.ions` (concentrations only for chloride and acetate salts); curation rules can match `ions_any` / `ions_none`.
- `targets.yaml` batch `nucleic-acid-1`, the brief's six nucleic-acid pilot molecules: add adenine riboswitch aptamer (`URS000080DF85_672`, 13 structures + 1 Rfam hit), human telomeric G-quadruplex (`DNA-6f16b68e4fba`, anchor 143D, 14 structures + 25 BMRB), preQ1-I riboswitch aptamer (`URS000080E020_32630`, 3FU2 construct: 1 structure + 1 BMRB; the cryo-EM que-PEC complexes carry it inside a 47-nt transcript and are skipped), HIV-1 TAR apical 29-mer (`URS000080E14B_11676`, 19 structures + 12 BMRB), Tetrahymena P4-P6 (`URS000080E052_32630`, 9 structures; 47 whole-ribozyme entries skipped) and the SARS-CoV-2 frameshift element (`URS00021ED9B3_2697049`, 6XRZ: 1 structure + 2 BMRB + Rfam; ribosome-bound mRNAs skipped). Curated: riboswitch and G-quadruplex; the other four are evidence-only.
- Draft curation `curation/URS000080DF85_672.yaml` (add riboswitch): ligand-free (5E54), ligand-bound intermediate (5SWD) and adenine-bound (1Y26) states, all observed, with riboswitch vocabulary labels on the apo and bound states. The bound state carries its dot-bracket, built from FR3D canonical pairs of 1Y26 (BGSU RNA 3D Hub) and checked by the validator. 10 of 13 items mapped (7 curator, 3 by rule); 6VWT/6VWV (crystal phase-transition snapshots) and the Rfam hit are left unmapped. ## WP1: SASBDB salt, ions and construct variants (2026-10-20)

`conformome/sources/sasbdb.py` now reads what the deposit writes in free text and turns it into
structured conditions. SASBDB has no salt field, so the information is spread over
`experiment.sample.name`, `experiment.sample.buffer.name`, `.additive`, `.comment` and the molecule
long/short names and descriptions.

- `normalize_text()` folds Unicode subscripts and superscripts (K₂HPO₄ → K2HPO4), the micro sign,
  thin/ideographic/non-breaking spaces and en/em/minus dashes into plain, single-spaced text. Every
  pattern runs on that form.
- `salt_ions()` returns `conditions.ions` (`{ion, concentration_mM}`) for salts of a metal or
  ammonium cation with a halide or sulfate. Buffering agents (HEPES, Tris, MES, acetate, citrate,
  phosphate, glycine) are **not** salts and their concentration is never taken as one. A salt named
  without a number comes back at `null`, not a guess. A buffer string is split on commas and
  semicolons and read component by component, so "100 mM NaCl, 50 mM Tris" gives Na+ = 100, and the
  figure written **before** a name wins over one after it. Fields quote each other, so each is read
  alone and the highest figure per ion wins (a buffer written twice is not counted twice).
- `conditions.salt_mM` is the sum of the quantified salt ions, or `null` if any ion's amount is
  unknown. The old code took the leading number of the buffer name, so "20mM HEPES" became a 20 mM
  salt for every alpha-synuclein deposit.
- `construct_labels()` fills `construct.labels` from mutation strings (C291A, K317C…), isoform
  tags (2N3R/2N4R, Isoform Tau-F), His/GST/… tags, sequence ranges and "WT". Chemical formulas in a
  buffer are kept out by lookarounds, so MgCl2/NaH2PO4/D2O are never read as mutations. Only tokens
  the deposit writes down; nothing is inferred from sequence.
- `conditions.notes` keeps the raw buffer and sample strings and states the salts found, or that the
  deposit states no salt.
- **Deliberately not used as a gate**: the structured `uniprot_range_first`/`uniprot_range_last` on
  the molecule (present on 189 of 224 records). It is a construct attribute, but it is filled in
  unevenly, so putting it in `construct.labels` would make comparability depend on how carefully a
  depositor filled a form. The lysozyme fibril pair SASDMJ4 (range 19-147) and SASDMY3 (range blank)
  is the same sample from the same paper at the same conditions; a range gate would drop the one real
  conflict this release has. Only a range the deposit *writes in text* ("residues 297-391") becomes a
  label. If ranges are ever used, they need a "blank does not contradict a value" rule, which the
  current "unknown does not match unknown" comparability does not have.

### Effect on conflicts (measured on identical build inputs)

Re-running the SASBDB parse over every molecule with both parsers on the **same** mappings (only the
conditions differ), and recomputing conflicts: mapped evidence **5,134 → 5,134** (the parser emits
the same 224 SASBDB records, only with richer conditions), conflicts **0 → 1**. The single surviving
conflict is real: hen lysozyme amyloid fibrils SASDMJ4 vs SASDMY3 (Rg 3.02 vs 3.84 nm, z = 53).
`not_compared` falls as SASBDB pairs become comparable: P37840 222 → 211, P00698 1454 → 1443.
A full `make site` + `make validate` over all 83 molecules reports **0 errors**.

Against the tagged release `v0.1.0` (52 conflicts, all SASBDB Rg), the parser **removes 32 and leaves
20 comparable (1 of which still trips 3σ)**. The removed α-synuclein pairs and their codes:

| Removed α-synuclein conflicts (state `aS-disordered`) | SASBDB codes |
| --- | --- |
| salt 0 vs 50 mM NaCl (6) | SASD2J3/2K3/2L3 × SASD2M3/2N3 |
| salt 0 vs 100 mM (9) | SASD2J3/2K3/2L3 × SASD2P3/2Q3/2R3 |
| salt 0 vs 150 mM (9) | SASD2J3/2K3/2L3 × SASD2S3/2T3/2U3 |
| salt 50 vs 150 mM (3) | SASD2N3 × SASD2S3/2T3/2U3 |

Lysozyme: SASDPT4/PV4/PZ4/UE4 drop out because the deposit states **no sample temperature** (the
older rule compared them anyway). Tau: SASDV56 vs SASDV66 drop out on construct labels (ubiquitin
linked at C317 vs C353). **The K→R note in the previous handoff was wrong**; these deposits are the
WT arm of a salt series, and the salt is now what separates them.

### Scope decisions (this PR does only the SASBDB line of WP1)
