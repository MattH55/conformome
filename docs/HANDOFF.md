# Handoff

State of Conformome on 2026-10-19, for whoever picks it up next. Read this first, then `README.md`, `docs/METHODS.md` and `docs/PILOT_REPORT.md`.

## What it is

A static website and the pipeline that builds it: one page per protein (keyed on UniProt accession) listing every experimental entry that has probed the protein's conformation, from each technique's own angle, mapped onto shared conformational states. Each state and model is labelled **observed** (resolved directly by a structure) or **inferred** (fitted to indirect measurements, with its assumptions listed). Every number on the site is regenerated by `make`; nothing is hand-edited HTML.

Sister project: SMASH-BIO (https://smash-bio.org, repository `MattH55/smash-bio`). Conformome reads its release file; it does not use or copy its code.

## How to run it

```sh
pip install -e ".[test]"        # Python 3.11+
make download                   # network; about 45 minutes for 81 proteins from an empty cache
make site                       # ingest -> map -> models -> site/dist/
make validate                   # site + schema, reference, licence, link and search checks + tests
ACC="P69441 P0DP23" make site   # limit to some proteins
```

Raw downloads go to `data/raw/` (git-ignored, with an HTTP cache in `data/raw/_cache` that never expires; delete it to refetch). `data/MANIFEST.json` (committed) records every raw file's URLs, date and SHA-256.

## How it is built

| Step | Code | Output |
|---|---|---|
| download | `conformome/pipeline.py: download`, one module per source in `conformome/sources/` | `data/raw/<source>/<acc>.json` |
| ingest | `pipeline.ingest`; each source's `parse()` | `build/<acc>/evidence.json`, `ingest.json` (what was skipped and why), `molecule.json` |
| map | `pipeline.map_protein`, `mapping/rules.py`, `mapping/conflicts.py` | `build/<acc>/mapped.json` (states, mappings, ambiguous items, conflicts, coverage grid) |
| models | `pipeline.models` | representative PDB/mmCIF files for observed states |
| site | `conformome/site/build.py` | `site/dist/`: home, `proteins/`, `protein/<acc>/`, `technique/<id>/`, `search/`, `about/`, `downloads/` |
| validate | `conformome/validate.py` | error list; CI fails on any |

Record types and their JSON Schemas are in `schema/`. Techniques (basis, prediction flag, observables) are in `taxonomy/techniques.yaml`; evidence with a technique or observable not listed there fails validation.

## Curation

- `targets.yaml` lists every protein built, with the batch it came from (`pilot-1`, `pilot-2`, `multi-source-1`). The validator requires every curation file to be listed.
- `curation/<acc>.yaml` holds states, curator assignments (by evidence ID or `pdb:` ID) and rules. Field reference: `curation/README.md`.
- Rules match on technique, source, ligands, ligand text, title words and publication title. Each mapping cites `rule:<id>` with its confidence and justification. A curator assignment wins over rules; items matched by rules for different states stay unmapped and are listed as ambiguous.
- Review the low-confidence rules first (list in `docs/PILOT_REPORT.md`).

## Deployment

- `.github/workflows/deploy.yml` runs on every push to the default branch (and by hand): download → `make validate` → publish `site/dist`. It takes about 15 minutes with a warm cache.
- `data/raw` is cached per ISO week, keyed on `targets.yaml` and the curation files: pushes within a week reuse it, and each new week refetches everything.
- Deploys queue instead of cancelling, so a long build can save its cache.
- `.github/workflows/ci.yml` runs the same validation on pull requests.
- `.github/workflows/build-all.yml` runs the full download and build for every molecule on pushes to `claude/**` branches (and on demand) without publishing. It uploads `site/dist`, `build-summary.md` (one row per molecule, from `python -m conformome.summary`), the manifest and any download failures as the `conformome-site` artifact (kept 14 days). `build/` is not uploaded because it holds records whose licence forbids redistribution.
- Pages must stay on **Source: GitHub Actions**. On "Deploy from a branch", GitHub publishes the README instead of the site.
- The root `CNAME` file was created by GitHub when the custom domain was set; `site/dist/CNAME` is written by the build.
- Links to repository files use `blob/HEAD`, because there is no `main` branch. If the default branch is renamed, nothing else needs to change.

## Known issues

1. **False conflicts**: 33 of the 52 flagged conflicts (alpha-synuclein, SASBDB) compare K-to-R mutants at different salt. SASBDB summaries record neither the mutation nor the salt separately.
2. **Paralogs**: CALM2 and CALM3 entries (identical sequence to CALM1) are not on the calmodulin page.
3. **Empty inferred states**: 5 inferred states have no evidence (unfolded BPTI, CI2, spectrin SH3, Pin1; cyclophilin A minor state).
4. ~~Unmapped fibrils~~ Fixed: hen lysozyme now has an observed `HEWL-fibril` state (representative 9J0L; polymorphs 9J0L/9J0M/8QV8 pooled, rule `hewl-fibril-structures`, medium confidence). Draft, unreviewed; whether polymorphs deserve separate states is a curator call.
5. **Skipped entries**: 14 powder-diffraction entries are skipped (could count as `xray`).
6. **RMSD rule**: implemented and tested, not run (it needs coordinates for about 17,000 entities).
7. **Missing content**: no transitions, no fitted models for inferred states, isoforms only partly handled.

## Taxonomy additions (2026-10-19, from the build brief)

- New techniques: `xray_time_resolved`, `cryoem_heterogeneity`, `ped_ensemble`. NMR dynamics also lists RDC and PRE observables. No source emits the new ids yet (PDB maps still use `xray` / `cryoem`; PED is a stub).
- Every technique now has `tier` (1, 2, 3, or null for predictions), `raw_location` and `raw_format`; the validator requires them.
- `schema/evidence.schema.json` now **requires** `data_level` (raw | processed | reported); `data_format` and `reader` are optional. Set per source: PDB, BMRB, SASBDB, AlphaFold DB and MDDB = `processed` (no source links raw images, FIDs or traces yet); DisProt and SMASH-BIO = `reported`. Raw-data pointers (EMPIAR, SBGrid, BMRbig, SMASH-BIO trace links) and `reader` sidecars are not populated.
- The coverage grid shows the best data level per cell (`coverage.data_levels` in `mapped.json`).
- Nucleic-acid techniques added (from the second brief): `shape`, `dms_mapseq`, `duplex_crosslinking`, `mutate_and_map`, `na_footprinting`, `uv_melting`, `native_gel_mobility`, and predictions `na_secondary_prediction`, `na_3d_prediction`. No source ingests them yet.

## Molecule schema (2026-10-19)

- Records are keyed on `molecule_id` (was `uniprot`) in every schema. Patterns: UniProt (isoform suffix allowed), RNAcentral `URS…`, `DNA-<12 hex of SHA-256 of sequence>` (`conformome/molecule.py: dna_id`), `CPX-…` for complexes. For proteins the ID is unchanged, so URLs and curation file names are unchanged.
- `schema/protein.schema.json` is replaced by `molecule.schema.json` (`molecule_type`, `identifiers` for UniProt/isoform/RNAcentral/Rfam/GenBank/NAKB/PDB, `modifications` (UniProt "Modified residue" features fill it for proteins), `components` for complexes). The build file is `build/<id>/molecule.json` and the all-records download uses `record_type: molecule`.
- New: `mutational_effect.schema.json`, `state_vocabulary.schema.json` and six vocabularies in `taxonomy/state_vocabularies/` (DOIs checked against Crossref). States gain `secondary_structure`, `family_label`, `population`; evidence gains `profile`; transitions gain `kinetics` (Φ-values as a profile); models accept `dot-bracket`; conditions gain required `ions`; mappings gain optional `agreement` (score + method, for profile-vs-dot-bracket mapping).
- Applied: GPCRdb labels on β2AR states, KLIFS labels on three Abl states (draft, unreviewed).
- Not done: complexes (`ingest` raises NotImplementedError), probing sources (RMDB, RASP) and for mutational effects and kinetics (ProThermDB, mega-scale dataset, MaveDB, ClinVar, PFDB), profile-to-dot-bracket mapping, the six nucleic-acid pilot molecules, and site pages for non-protein molecules.

## Nucleic-acid sources (2026-10-19)

- `conformome/rnacentral.py` builds RNA molecule records (like `protein.py` for UniProt). RNA pages are keyed on the species-specific `URS…_<taxid>`.
- `conformome/dna.py` builds DNA records from the `anchor_pdb` given in `targets.yaml`; the anchor's DNA chain is the sequence, and the target's `molecule_id` must equal `dna_id(sequence)`.
- `sources/nakb.py` (RNA and DNA): NAKB's Solr index (`/node/solr/nakb/select`, linked from its download page; there is no documented API). Candidates: chains of exactly the molecule's sequence (`naseq`), entities RCSB's sequence search finds at >=90% identity, and, for RNA, chains Rfam assigns to the same family in the same organism. Other constructs must be 0.8-1.25x the molecule's length, so larger RNAs containing it (whole introns around P4-P6, mRNAs in ribosomes) are skipped with a reason. When RNAcentral files the molecule as a synthetic construct (taxon 32630), the organism is taken from NAKB's exact-sequence chains. Each item says which rule matched.
- `sources/rfam.py` (RNA): one `rfam_covariation` item per family hit, flagged as a prediction. The family consensus (`SS_cons`) is kept in the raw file but not projected onto the sequence (needs Infernal `cmalign`).
- Sources declare `MOLECULE_TYPES`; protein sources default to proteins only. BMRB is queried for RNA and DNA by BLAST on the sequence (>=90% coverage and identity): the telomeric G-quadruplex gets 25 entries, the riboswitch none. SASBDB is not yet queried for nucleic acids. BMRB sample components fill `conditions.ions` (concentrations only for chloride and acetate salts); curation rules can match `ions_any` / `ions_none`.
- `targets.yaml` batch `nucleic-acid-1`, the brief's six nucleic-acid pilot molecules: add adenine riboswitch aptamer (`URS000080DF85_672`, 13 structures + 1 Rfam hit), human telomeric G-quadruplex (`DNA-6f16b68e4fba`, anchor 143D, 14 structures + 25 BMRB), preQ1-I riboswitch aptamer (`URS000080E020_32630`, 3FU2 construct: 1 structure + 1 BMRB; the cryo-EM que-PEC complexes carry it inside a 47-nt transcript and are skipped), HIV-1 TAR apical 29-mer (`URS000080E14B_11676`, 19 structures + 12 BMRB), Tetrahymena P4-P6 (`URS000080E052_32630`, 9 structures; 47 whole-ribozyme entries skipped) and the SARS-CoV-2 frameshift element (`URS00021ED9B3_2697049`, 6XRZ: 1 structure + 2 BMRB + Rfam; ribosome-bound mRNAs skipped). Curated: riboswitch and G-quadruplex; the other four are evidence-only.
- Draft curation `curation/URS000080DF85_672.yaml` (add riboswitch): ligand-free (5E54), ligand-bound intermediate (5SWD) and adenine-bound (1Y26) states, all observed, with riboswitch vocabulary labels on the apo and bound states. The bound state carries its dot-bracket, built from FR3D canonical pairs of 1Y26 (BGSU RNA 3D Hub) and checked by the validator. 10 of 13 items mapped (7 curator, 3 by rule); 6VWT/6VWV (crystal phase-transition snapshots) and the Rfam hit are left unmapped. No expression-platform states: the construct is aptamer only. Every state rests on X-ray alone. BMRB has no entries for this aptamer (BLAST on the 71-nt sequence finds only 13-21 nt fragments of other RNAs; a text search finds none); smFRET, force and SHAPE data are not ingested yet.
- Draft curation `curation/DNA-6f16b68e4fba.yaml` (human telomeric G-quadruplex 22AG): parallel (1KF1), antiparallel (143D) and hybrid (2E4I) states, labelled with the G-quadruplex vocabulary. Every structure's topology was computed from its coordinates with `conformome/g4.py` (G-tract directions on the stacking axis): 10 K+ crystals parallel, 3 NMR structures antiparallel, 1 hybrid. BMRB shift entries are mapped by title words or by Na+-without-K+ at low or medium confidence. 24 of 39 items mapped; BMRB 34714 (ligand-induced hybrid-to-antiparallel change) is ambiguous, which is right: it is transition evidence with no rate yet. Hybrid-1 and hybrid-2, and basket and chair, are not separated into substates.
- Pages for RNA and DNA still live under `protein/<id>/`; the header line is worded per molecule type.
