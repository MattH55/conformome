# Contributing

## Correcting a page

Every page has a link to its curation file. To correct a state, a mapping or a description:

1. Open `curation/<UniProt>.yaml` on GitHub and propose an edit, or open an issue that names the page and the change.
2. Each mapping needs a `curator`, a `confidence` (high, medium or low) and a one-line `justification`. Say which evidence ID (for example `EV-PDB-4AKE-1`) and which state.
3. Inferred states need `assumptions`. A state is not inferred because its evidence is indirect; it is inferred when a model is fitted to it.
4. Run `make validate` before opening a pull request. It checks the schemas, the references between records, the taxonomy, the licence rows and the site.

## Adding evidence

Evidence comes from sources, not from hand entry. Add or fix a source module in `conformome/sources/` following the contract in `conformome/sources/base.py`, record its licence in `docs/SOURCES.md`, and add a fixture if the parser changes.

## Adding a technique

Add it to `taxonomy/techniques.yaml` with its basis (observed or inferred), whether it is a prediction, its resolution class and the observable types it reports. The validator rejects evidence whose technique or observable is not listed.

## What not to change by hand

Do not edit anything under `site/dist/` or `build/`. They are regenerated by `make site`. Do not edit `data/MANIFEST.json` by hand; it is written by `make download`.

## Ground rules

- No data that a licence forbids redistributing. Link to it instead.
- Nothing extracted from literature goes live without human review.
- Conflicts are shown, not averaged away.
