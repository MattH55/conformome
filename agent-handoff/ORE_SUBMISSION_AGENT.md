# Instructions for a coding agent: prepare the Conformome article for Open Research Europe

You are preparing the Conformome manuscript for submission to Open Research Europe (ORE). You build and check every file, and you write the answers for the submission form. **The author submits.** You do not create an ORE account, log in as the author, accept declarations, or press Submit. You do not publish a release or mint a DOI.

Read this file first. Where it conflicts with an older brief (`paper/BRIEF.md`, `paper/ore_submission.md`), this file wins. `agent-handoff/AGENT_INSTRUCTIONS.md` still governs the release, the data archive and the licence rules; this file points to it rather than repeating it.

## 2. Ground rules

- Never type a corpus number by hand. Add a tag, then run `fill_numbers.py --write`.
- Never invent curation, licences, ORCIDs, references, DOIs, reviewer details or audit results.
- A new reference needs a DOI checked against Crossref and a CSL-JSON entry in `paper/references.csl.json`.
- Do not revert the 3σ conflict rule, the ion comparability rule, the word-boundary mapper, the licence allow-list (`zenodo/redistribution.yaml`) or the source parsers.
- Do not add a "Validation of the mapping" subsection, and do not commit audit responses.
- If a tool is missing, say which one, and do not claim that the file it would have made exists.

## 3. Freeze the release and build the archive

Follow `agent-handoff/AGENT_INSTRUCTIONS.md` §1, §4 and §5. In short:

1. `make site`, then `python -m conformome validate` (0 errors) and `python -m pytest -q` (all pass).
2. `python -I paper/scripts/stats.py`, then `fill_numbers.py --write`, then `fill_numbers.py --check`.
3. Commit. Create the tag `v0.1.0` **locally** on that commit. Do not push the tag.
4. Run `stats.py` again so that `release.tag` and `release.commit` are recorded. `python -I paper/scripts/stats.py --check` must pass, which means the site pages agree and HEAD is tagged `v0.1.0`.
5. Write `scripts/check_release_metadata.py` and a `zenodo-prep` Makefile target; `scripts/make_data_release.py` is already on the branch. Run `make zenodo-prep` twice; the second `release/` must be byte-identical. SMASH-BIO must appear in `EXCLUDED.tsv`.
6. Write `release_meta/release_notes.md`, and put the `gh release create v0.1.0 --draft …` command in the PR. Do not publish the release.

If a later change moves any count, delete the local tag, rebuild, re-run steps 2–4 and tag again.

After submission, post-publication peer review is open. Reviewer comments come back to the author. An agent may draft responses and a revised version from the same `paper/ore` workflow (edit `manuscript.md`, rebuild, re-check), but the author sends them.
